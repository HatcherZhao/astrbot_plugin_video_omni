# 视频全模态理解 0.2.1

插件通过 video_omni_understand 把视频理解作为工具结果交还主模型。保留用户原消息及会话身份，不拦截链接、不自动输出固定摘要。

主模型决定是否需要观看以及后续如何处理。群聊遵守 AstrBot 原有唤醒规则。Parser X 发出视频和简介后，本插件会在同一已唤醒事件中恢复一次主模型请求，保留原话、会话与发送者身份。

video_omni_frames 按模型选择的秒数从原片提取至多六张截图；MiniMax Office 已启用且当前用户满足其权限时，登记为该用户的输入文件并返回 file_id / input_name。否则仍返回截图路径，不自动发图。当前适配 MiniMax Office 1.0.0 的可信附件接口，后续接口变化需复验。

长任务在原会话工具调用中等待，视频工具调用期间单独放宽超时，完成后恢复原限制；主模型收到单个工具结果继续，保留群成员身份。取消时回收下载子进程。无需新服务。

配置保留百炼模型、Cookie、画质、时长、缓存及并发限制。旧 notice / prompt 字段不再生效：用户任务与主模型提问决定分析重点。

## 使用

在 AstrBot 插件管理中安装或更新本仓库，填写百炼 API Key，并启用支持工具调用的主聊天模型。私聊直接提出要求；群聊按现有唤醒规则 @ 机器人。

- “这个 B站视频讲了什么？”：主模型可观看后直接回答。
- “把这个视频整理成 Word，附关键操作截图”：主模型可观看、提取截图，再调用已安装的文档工具交付文件。
- “比较这两个视频的做法”：主模型分别取证后进行对比。

视频插件不执行邮件、转发等最终动作，主模型依据用户要求、已有工具和权限继续处理。只支持当前下载器可处理的 B站 BV/av 视频链接；b23 短链接需先解析为完整链接。截图不重新生成画面，仍可能受原视频清晰度限制。

## 从 0.1.x 升级

旧版“收到链接即后台总结”的行为已移除，原有 notice / prompt 配置不再生效。API Key、Cookie、画质和缓存配置保留。无需修改 AstrBot 核心或重启 QQ 桥。要求 AstrBot >= 4.29.3；MiniMax Office 截图登记适配 1.0.0，后续接口变化需复验。

## 验证

在已安装 AstrBot 4.29.3 及其依赖的环境中，从仓库根目录运行：

```bash
python -m unittest discover -s tests -v
```

测试覆盖原始请求保留、工具结果返回、真实 AstrBot 工具执行器的超时隔离、取消回收、失败反馈和截图权限隔离。测试不调用付费模型、不发送聊天消息。视频下载依赖 yt-dlp、ffmpeg 和 ffprobe。
