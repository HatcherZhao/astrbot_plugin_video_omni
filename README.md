# 视频全模态理解

把整段视频直接交给多模态模型看完，而不是抽几张截图猜。

## 它解决什么问题

市面上常见的视频理解方案是「抽帧 → 逐帧描述 → 音轨转文字 → 拼起来」，问题很实在：

- **抽帧必然漏**。20 分钟的视频抽 16 帧，两分钟才看一眼，中间的转折、图表变化全丢了；
- **拼起来会失真**。画面描述和字幕是两条流水线，时间对不齐，模型最后拿到一堆碎片；
- **慢**。抽帧、转写、再合并，一轮下来好几分钟，等不及的对话早就超时了。

这个插件换个做法：视频压小一点，整段扔给 `qwen3.8-omni` 系列。那个模型自带音频通道，**画面和声音是同一遍看完的**，时间轴天然对齐，图表上的小字也读得到。

## 特点

- **不卡对话**：收到链接先应一声，后台跑完再把结果单独发出来。处理失败也只说一声，不会把消息吞掉；
- **不依赖宿主模型**：自带百炼 key 配置，你主模型用 OpenAI、DeepSeek 还是本地部署都不影响；
- **不给别人添麻烦**：不装任何解析插件也能用，自己带 yt-dlp 下载；装了的话会顺手复用它的缓存，省一次下载；
- **花费看得见**：结果末尾附 token 用量、大概花了多少钱、request_id，方便去百炼控制台对账。

## 安装

```bash
cd /你的/astrbot/data/plugins
git clone https://github.com/HatcherZhao/astrbot_plugin_video_omni
pip install yt-dlp        # 没有的话装一个
```

系统里还需要 `ffmpeg` / `ffprobe`（大多数发行版 `apt install ffmpeg` 即可）。

在 AstrBot 面板启用插件，填上百炼 API Key。

## 配置

| 配置项 | 说明 |
| --- | --- |
| 百炼 API Key | 必填，`sk-` 开头 |
| 多模态模型 | 默认 `qwen3.8-omni-flash`；换 `qwen3.8-omni-plus` 效果更好，价格翻倍 |
| API 地域 | 北京 `dashscope.aliyuncs.com`，新加坡 `dashscope-intl.aliyuncs.com`，跟 key 对应 |
| 压缩画质 | `auto` = 15 分钟内 480p、更长的 360p。480p 能看清图表小字，360p 省一半 token |
| 时长上限 | 默认 60 分钟，按钱包设。模型本身最多 2 小时 |
| B站 Cookie | 可选。不填也能下 480p，填了画质更稳、少被风控 |
| 复用缓存目录 | 可选。填了就去找别的插件下好的同名文件 |

## 用法

群里直接发 B站链接，或者只发 BV 号：

```
https://www.bilibili.com/video/BVxxxxxxxxxx
```

如果链接后面还带了话，会当成额外的问题一起交给模型：

```
BVxxxxxxxxxx 这里面提到的数据你能帮我列一下吗
```

## 花钱参考（实测）

一条 20 分 54 秒的财经视频，480p：

- 输入 165,550 token（画面 156,674 + 声音 8,773 + 文字）
- 输出 1,200 token
- **约 ¥0.14**

同一条换 360p，输入降到约 10 万 token，**约 ¥0.09**，代价是图表小字可能读不准。

压缩是最慢的一步：8 核机器上 20 分钟视频压 480p 要两分半到三分钟，之后上传 20 秒、推理 40 秒。压过的文件会缓存，同一条视频再问就快了。

## 已知限制

- 只认 B站链接（BV / av 号）。其他平台可以自己把文件放进工作目录，按 `{BV号}.mp4` 命名；
- 超过 2 小时的视频模型吃不下，插件会在时长上限那里就拦住；
- 摘要太长时会被 `max_tokens` 截断，末尾会有提示。
